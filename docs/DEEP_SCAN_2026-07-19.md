## 1. App synchronization (web ↔ data ↔ Telegram)

```
Web portals (student/admin/master)
        ↓ cookies / JWT
MongoDB (Prisma · 132 models · Pay mapped + Play unmapped)
        ↑ webhooks / confirm jobs
Payment rails (TON, Mbiyo, LivePay, Relworx, Vixon, OpenPay card)
        ↓ notify
Telegram bot DMs + TMA (/tma) + Play clicker (/clicker)
```

**Sync strengths:** payment confirm → Telegram notify; TMA session cookies share student/admin APIs; hub hide/maintenance gates public layouts.

**Sync gaps (remaining):** Play `User` vs tuition `Student` identity; TMA amount UI decorative; orphaned bot TON menu; Play broadcast ≠ tuition students.

## 2. MongoDB / Prisma (no omission summary)

- **132 models** in `prisma/schema.prisma` (Mongo provider).
- Apply via **`prisma db push`** (no SQL migrations) — prod must push after schema changes (hub hide, visit paths, etc.).
- **Fixed this pass:** LivePay / Relworx / VixonPay / TON confirms use `updateMany({ status: "pending" })` before side effects (idempotent CAS).
- **Still open (BACKLOG):** refunds status-only; school allocation not one transaction; missing unique on `admissionNo` / `schoolPayCode`; sparse `withPrismaRetry` on money paths.
